## A. hawk(KeyValueStore 一次性迁移通道)退役评估

### A.1 现状(证据)

- 全仓 `com.orhanobut.hawk` 依赖只剩 **core-storage**(`build.gradle:38`),import 只剩
  `core-storage/.../config/KeyValueStore.java:5`;`app/proguard-rules.pro:101` 有 hawk keep(可一并删)。
- `KeyValueStore` 现**全部调用点**都是 `contains → get → 迁(DataStore/文件/新键)→ delete` 的
  一次性 legacy 读取,已无活跃 `put`(读码确认):
  - SystemConfig(loading_anim 等 move*)、PrefsDataStore 注释、DefaultLogConfigStore(log 开关/级别);
  - DownloadStore/DownloadPolicy/DownloadArchive(HAWK_KEY 下载任务/档案/并发/WiFi 旧键);
  - PlayConfig、LiveConfig(直播历史/频道播放覆写 173-202)、HomeHotCache、SubscriptionConfig(订阅/搜索域)、
    RemoteTVBox(遥控记忆)、spider ApiConfig(822-825 getString 后 delete)、`spider util/js/local`(js 运行时缓存)。
- 数据现状:DataStore(运行权威)与下载任务/档案文件已在各域迁移并**删旧键**;Hawk 已从"通用键值存储"
  退化为"读一次旧键就删"的迁移通道。

### A.2 退役条件(必须先满足)

1. 至少一个**已发布版本**搭载上述"按访问迁移 + 删旧键"逻辑(现状版本已满足,即本评估所在分支);
2. **旧版本→当前版本 升级数据回归**通过:订阅列表/勾选源、直播历史与频道配置、播放设置、下载任务与档案、
   日志开关、遥控记忆、首页/历史条数等在升级后保留(device-regression-checklist 新增一组);
3. 并行批合流提交后再动(避免与 SelectDialog/首页批交叉)。

### A.3 建议步骤(分两版)

> ✅ **进展(已实施版 N)**:`KeyValueStore` 已无 hawk 化——init 占位、旧键读取默认值、put/delete 空操作,
> core-storage 移除 hawk 依赖、App 装配去掉 init、proguard keep 删除(4b775b18/3d9d9dcc,门禁全绿)。
> 遗留:各域 legacy 分支(contains/get/delete 调用点)仍在但自然失效,待版 N+1 与旧版升级回归同批删除。

- **版 N(无 hawk 化灰度)**:`KeyValueStore` 改为空实现/直读 DataStore+默认值(不再 Hawk.init、不再读 Hawk),
  保留 API 与调用点(编译零改动),legacy 分支自然失效;旧版升级者若曾运行过迁移则无感,未运行过的
  丢旧键但 DataStore/文件已权威(影响仅限"上一版都没打开过对应功能"的极端用户);
- **版 N+1(清代码)**:删 core-storage hawk 依赖、KeyValueStore 文件与全部 legacy 分支(改默认值),
  删 proguard keep;`App.initParams` 去掉 `KeyValueStore.init` 顺序依赖;检查 PrefsDataStore 注释。
- 风险点:spider ApiConfig/`local`、LiveConfig 频道覆写、RemoteTVBox 等"get 后删"通道必须与 KeyValueStore
  同生命周期,不能只删一半。

## E. 已发现的问题(待语料+真机验证后修)

- **FormatASS 样式段疑似解析缺陷(潜藏)**:逐行读码 + JVM 探针复现——外层 while 在
  "[Script Info]" 等段内循环读到下一个段头 `[...]` 后,循环体底部仍执行 `line = br.readLine()`,
  把下一个段头(如 `[V4+ Styles]`)所在行吞掉,导致 **Styles 段永不进入**(探针结果
  `styling.size=0`、dialogue 报 "undefined style: Default",且伴 "unexpected end of file" 提示)。
  影响:`.ass` 字幕文本可显示,但字号/颜色/对齐等样式全部丢失;同理多 `Style:` 行也只会取到一段。
  修复方向:段内循环因命中 `[` 退出时应"回看"该行(跳过底部 readLine 或置 lookahead 标志),
  并需真实 `.ass` 语料(多 Style/字体/颜色/对齐)与真机渲染比对后再动,故暂不修复。
  (复现样例与 FormatASSTest 同构;未提交任何失败测试)

- **Style.getRGBValue 十六进制颜色分支错位(同类潜藏缺陷,读码证据)**:`&HAABBGGRR`(ASS)分支对
  `&H00FFFFFF` 做 `substring(8)+substring(6,7)+substring(4,5)+substring(2,3)`,输出错序丢半字节
  (如得到 `FFFFF0` 而非 RRGGBB 语义);`&HBBGGRR` 分支同理。当前被样式段解析缺陷掩盖(样式未解析),
  待样式段修复后一并处理并配真机颜色比对;单测不锁定错值。
